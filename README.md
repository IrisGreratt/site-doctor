# 🩺 Site Doctor — 网站健康诊断工具

输入一个网址，自动检查 SSL 证书、响应速度与安全配置，输出 **0–100 分** 的体检报告和中文改进建议。

> 个人项目 / 用于简历与面试展示。核心目标是：**小而完整、能真实运行、有可以讲的工程点**。

---

## 功能

| 检查项 | 说明 | 满分 |
| --- | --- | --- |
| 可达性 | 站点能否正常建立连接并返回响应 | 25 |
| 状态码 | HTTP 2xx / 3xx / 4xx / 5xx 分级评分 | 10 |
| 响应速度 | 按耗时档位给分（≤300ms 满分，>5s 零分） | 15 |
| HTTPS 证书 | 是否启用 HTTPS、证书是否有效、剩余天数 | 25 |
| 安全响应头 | HSTS / CSP / X-Content-Type-Options / X-Frame-Options / Referrer-Policy | 25 |

评分的同时输出对应建议，分数低的地方一定能在建议里找到原因。

## 快速开始

```bash
cd site-doctor

# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动服务
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3. 浏览器打开
# http://127.0.0.1:8000
```

输入网址（可以不写 `https://`，会自动补全）即可看到报告。

> Windows 下如果 `--reload` 报 `WinError 5`，去掉 `--reload` 参数即可。

## 运行测试

```bash
python -m pytest -q
```

测试全部离线运行（网络调用用 mock 隔离），共 33 个用例，覆盖 URL 整理、安全头检测、各评分档位与建议文案的对应关系。

## 项目结构

```
site-doctor/
├── app/
│   ├── main.py       # FastAPI 入口与路由（首页 = 表单 + 结果页）
│   ├── checker.py    # 诊断引擎：HTTP 请求、SSL 证书、安全响应头
│   └── scoring.py    # 评分与建议生成
├── templates/
│   └── index.html    # Jinja2 模板
├── static/
│   └── style.css     # 样式
├── tests/
│   ├── test_checker.py
│   └── test_scoring.py
├── requirements.txt
└── pytest.ini
```

分层思路：**checker 只负责「采集事实」，scoring 只负责「判断好坏」**。采集层不关心分数，评分层不发起网络请求，两边可以独立测试、独立修改。

## 有一定难度、面试可以讲的工程点

### 1. SSL 证书：为什么不能一上来就用 `CERT_NONE`

最初的做法是关闭证书验证（`verify_mode = ssl.CERT_NONE`）去读证书信息，结果 `getpeercert()` 返回 **空字典 `{}`** —— Python 在关闭验证时不会解析证书字段，只留二进制形式。

**解法：两次握手**

1. 先用**正常验证**握手，绝大多数站点走这条路，能直接拿到 `notAfter`、`issuer`；
2. 如果验证失败（自签名 / 过期证书），再降级为不验证，拿 `binary_form` 的 DER 字节，用 `cryptography` 库解析出过期时间。

这样既能对「证书正常」的站点给出完整信息，又能在「证书有问题」时告诉用户**具体是什么问题、还有几天过期**，而不是笼统地说“握手失败”。

### 2. 超时必须兜底，否则一个坏站点拖垮整个服务

所有网络请求都设了 5 秒超时，并把 `httpx.TimeoutException` / `http.HTTPError` 捕获成报告里的 `error` 字段，而不是让异常冒泡。实测访问国内无法直连的站点会稳定在 ~5s 返回“请求超时”，页面不会卡死。

### 3. 单项失败不影响整体报告

HTTP 请求失败时，**仍然会继续检测 SSL 证书**。否则会出现「网址写的是 https，报告却显示非 HTTPS 站点」这种自相矛盾的结果 —— 这个 bug 是在真实测试不存在的域名时发现的。

### 4. 分数和建议必须对得上

评分拆成 5 个维度，每个维度同时产出「得分」和「扣分原因」，建议文案直接来自扣分原因，避免出现“分数很低但不知道为什么”。

## 已知局限 / 后续可以做的

- 只检查首页，不检查子页面与静态资源；
- 单线程串行检测，且为同步阻塞调用；后续可改用 `asyncio` + 并发检查多个指标，缩短响应时间；
- 没有历史记录与定时监控（可加数据库 + 定时任务，做「证书到期提醒」）；
- 安全头判断只看是否出现，没有解析其取值是否合理（例如 CSP 是否过宽）；
- 没有部署上线，只在本地运行。
